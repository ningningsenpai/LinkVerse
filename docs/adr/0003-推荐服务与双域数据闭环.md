# ADR-0003：推荐服务与双域数据闭环

- 状态：已接受
- 日期：2026-09-03
- 决策者：LinkVerse 项目组

## 1. 背景与目标

Trade 需要一条可训练、可回馈、可重放和可回滚的推荐链路。后续 Forum 也需要推荐能力，但两个领域的对象、标签和业务过滤不同。本决策的目标是保留一套可共享的算法和服务基础，同时防止跨领域标签污染。

## 2. 当前约束与证据

- 当前只有 Trade 商品、订单和 Payment 支付事实；Forum 尚未建设，本期不创建空实现。
- 本地目录仅有少量种子商品，不足以支持推荐质量结论。
- 旧数据约含 10,000 用户、6,262 商品和 94,934 次合成交互，但缺少真实曝光负样本，且聚合字段存在未来泄漏。
- 旧模型存在任务头未注册、损失函数与激活函数不匹配、负采样污染、OOV 冲突和词表错位等阻断问题，旧 `.pth` 权重不可复用。
- 训练主机为 Windows RTX 4070 SUPER 12GB；在线运行时需使用 Linux CPU 容器。

## 3. 备选方案

| 方案 | 优点 | 代价与风险 |
|---|---|---|
| Trade 和 Forum 各建一个推荐服务 | 领域隔离直观 | 事件、训练、评估、发布和可观测性重复建设 |
| 单服务加领域适配器 | 共享框架，数据和模型仍可隔离 | 需要严格的领域契约和模型包校验 |
| 直接复用旧项目 | 初始代码量少 | 旧算法与数据缺陷无法提供可信基线，并引入只读快照的运行时依赖 |

## 4. 决策

新建一个独立 Python Recommendation 服务，采用 `DomainAdapter` 插件边界。共享事件模型、用户兴趣编码、时点特征、召回/排序/重排框架、指标、调参器、模型包和在线服务。Trade 使用独立数据集、对象塔、标签、索引和模型路径；未来 Forum 仅通过新适配器接入，不直接混合 Trade 标签。

首版算法使用时间衰减热门、新品、TF-IDF 内容、加权 ItemCF 和 GPU 双塔向量召回；通过归一化分数与 RRF 融合，使用 LightGBM LambdaRank 精排，最后以 MMR、配额和新品探索重排。当前规模使用 CPU `IndexFlatIP`。LightGCN 和深度多任务精排等真实交互达到启用门槛后再评审。

## 5. 数据所有权与一致性

Trade 和 Payment 持有业务事实并通过本地事务与 Outbox 保证一致性。Trade 只接受客户端上报已实际渲染的曝光和详情打开；用户、来源和模型版本必须由 delivery 服务端关联。Payment 的支付和退款事实由 Trade 幂等消费。

Java 导出器使用独立只读账号生成版本化匿名 JSONL 与 manifest，Python 在重复事件校验后固化为同版本 Parquet 快照；两步都不回写业务库。用户 ID 使用外部 Secret 做 HMAC，Python 只接触稳定匿名 `user_key`。训练只生成不可变模型包，不直接覆盖当前版本。

## 6. 失败模式与恢复

- Recommendation 超时为 800ms；20 次调用窗口失败率达 50% 时熔断 30 秒，并限制并发。
- Recommendation 失效时，Trade 使用数据库中的可售热门与新品降级，下单和支付链路不依赖推荐服务。
- 模型包的 Schema、词表、权重或索引 ID 不一致时拒绝加载。
- 新模型先校验和影子比较，再原子替换 `active-model.json`；失败时继续使用旧模型，回滚只恢复活动指针。

## 7. 可观测性与安全

Recommendation 不进入 Gateway 公网路由。Trade 调用所用服务 JWT 必须满足 `aud=linkverse-recommendation`、`scope=recommendation.internal`、`token_use=service` 和 `sub/client_id=linkverse-trade-recommendation`。快照导出、实验和服务日志不记录原始用户 ID。

指标标签只使用领域、模型状态、算法通道和结果等低基数枚举，禁止将用户、请求或商品标识放入指标标签。`REAL` 与 `SYNTHETIC` 数据独立统计、独立评估。

## 8. 验证标准

- 数据质量：脏行、重复事件、OOV、时间切分和未来泄漏均有自动检查。
- 离线指标：以 `NDCG@20` 为主，同时记录 `Recall@50`、覆盖率、多样性和延迟；最佳参数使用 3 个固定随机种子重训并报告均值和标准差。
- 接口闭环：覆盖曝光、详情、加购、下单、支付、退款、快照、重训和再推荐。
- 运行性：Windows GPU 训练必须显式验证 CUDA；Linux 容器执行 CPU 推断；同种子训练可复现。
- 性能：20 并发用户成功率不低于 99%，Python 内部推断 p95 不高于 300ms，Trade 推荐接口 p95 不高于 800ms。

## 9. 迁移与回滚

数据库仅提供向前兼容迁移：先添加可空列，完成回填后再收紧约束；新 API 字段保持可选，旧下单请求继续有效。Recommendation 通过 Compose `recommendation` profile 独立启用，可在不影响四个现有部署单元的情况下停用。

模型版本固定为 `trade-日期时间-git摘要-数据摘要`。候选模型只在 `NDCG@20` 同时优于热门基线和当前模型、覆盖率下降不超过 10% 且延迟达标时才能晋级。原始数据、Parquet、完整 trial、权重和 Faiss 索引不入库；合成数据结果不用于线上质量宣传。
