# LinkVerse MVP 阶段 1 与阶段 2 上传说明

## 1. 上传目标

本次上传将已完成并通过验收的 LinkVerse 求职 MVP 阶段 1、阶段 2 合并到远端仓库。上传目标为：

- 本地分支：`main`
- 远端名称：`origin`
- 远端仓库：`git@github.com:ningningsenpai/LinkVerse.git`
- 提交信息：`feat(mvp): complete phases 1 and 2`

本次提交以 [`04-MVP开发步骤与注意事项.md`](04-MVP开发步骤与注意事项.md) 和 [`ADR-0001`](adr/0001-MVP独立Payment服务边界.md) 为范围依据，不改变旧项目快照。

## 2. 上传内容

### 2.1 阶段 0 最小收口

- 增加 Payment 独立部署 ADR，冻结 Gateway、Identity、Trade、Payment 四个 Java 部署单元。
- 修正长期架构文档、MVP 文档和仓库指南之间的范围与模块命名。
- 固定 Java、Maven、Spring、容器镜像、端口、Schema、Nacos namespace/group 和数据所有权。

### 2.2 阶段 1

- 新增 Java 21 Maven Reactor、BOM、`platform-core` 和四个 `platform-starter-*`。
- 新增 Gateway、Identity、Trade、Payment 四个 Spring Boot 服务。
- 新增 MySQL、Redis、RabbitMQ、Nacos 本地 Compose 环境及精确镜像摘要。
- 新增本地秘密准备、中间件初始化和运行验证 PowerShell 脚本。
- 实现统一 Problem Details、请求 ID、结构化日志、最小 Actuator 暴露和 Nacos 服务发现。

### 2.3 阶段 2

- 实现账号注册、登录、BCrypt 密码保存和用户 JWT。
- 实现 Spring Authorization Server 的 `client_credentials`、JWK 和授权服务器元数据。
- 实现 Gateway 与三个资源服务的 JWT 档案校验。
- 实现 Trade 服务令牌获取与缓存，以及 Payment 内部接口的服务身份隔离。
- 保持 Provider 回调入口关闭，避免在验签业务完成前形成匿名入口。

## 5. 本地提交与远端上传

从仓库根目录执行：

```powershell
git status --short
git diff --check
git add --all
git commit -m "feat(mvp): complete phases 1 and 2"
git push origin main
```

上传后执行：

```powershell
git status --short
git log -1 --oneline --decorate
git ls-remote --heads origin main
```

验收标准为工作树干净，`main`、`origin/main` 指向同一提交，远端 `refs/heads/main` 返回相同提交摘要。

## 6. 回滚原则

- 上传失败时保留本地提交，修复网络或权限后重新执行 `git push origin main`。
- 已推送但需要撤销时，使用 `git revert <commit>` 生成可审计的反向提交，不重写远端 `main` 历史。
- 回滚代码不删除 Docker 数据卷，不删除本地 `.env` 或 RSA 密钥。
- 数据库迁移只追加；需要清理本地数据时必须单独确认，不在 Git 回滚中隐式执行。

## 7. 当前范围边界

- Forum、Python Recommendation、Elasticsearch 和前端；
- 历史用户或业务数据迁移、生产高可用与正式发布流程。
