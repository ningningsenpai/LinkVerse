# LinkVerse MVP 阶段 5：商品秒杀执行设计

## 1. 目标与范围

阶段 5 在 Trade 内实现单活动、单专用商品、每人一次、每次一件的最小秒杀。Redis 只负责快速准入，RabbitMQ 负责削峰，MySQL 条件扣减和唯一约束仍是订单与库存的最终防线。

不实现活动管理后台、购物车、优惠券、动态限购、多商品套餐或分布式锁。活动和商品使用 Flyway/local 演示数据初始化。

## 2. 数据结构

Trade 通过前向迁移增加：

| 表或变更 | 用途 | 核心约束 |
|---|---|---|
| `seckill_campaign` | 活动、专用商品、版本、时间窗和初始库存 | 活动号唯一；同一进行中商品只能属于一个活动 |
| `seckill_reservation` | 保存预约及最终结果 | `reservation_no`、`event_id`、`(campaign_id,user_id)` 唯一 |
| `consumed_event` | 消费幂等 | `(consumer_name,event_id)` 唯一 |
| `outbox_event` | 秒杀结果和库存释放事件 | `event_id` 唯一 |
| `trade_order.reservation_id` | 关联秒杀预约 | 可空且唯一；普通订单保持为空 |

预约状态固定为 `PUBLISH_PENDING/PUBLISHED/ORDER_CREATED/FAILED/EXPIRED/COMMITTED/RELEASED`。状态更新必须检查活动版本和前置状态。

## 3. Redis 与消息契约

Redis Key 使用同一 Cluster Hash Tag，并带 `lv:mvp:trade:` 前缀。Lua 原子执行：

1. 校验活动版本与时间窗；
2. 校验用户是否已尝试；
3. 校验并预扣库存镜像；
4. 保存稳定的 `reservation_no`、`event_id` 和载荷摘要；
5. 加入待发布有序集合。

补偿 Lua 只在预约号、活动版本和状态同时匹配时恢复库存，且永远不删除用户已尝试标记。

事件包括 `SeckillRequested`、`SeckillReservationSucceeded`、`SeckillReservationRejected` 和 `SeckillStockReleased`。所有事件复用版本化消息信封，使用稳定 `event_id`。

## 4. 外部接口

| 接口 | 行为 |
|---|---|
| `GET /api/v1/seckill/campaigns/{campaignId}` | 返回活动时间、商品快照和当前展示状态 |
| `POST /api/v1/seckill/campaigns/{campaignId}/reservations` | 用户 JWT + `Idempotency-Key`；准入成功返回 `202` 和排队状态 |
| `GET /api/v1/seckill/reservations/{reservationNo}` | 仅预约所有者可查；MySQL 终态优先，否则读取 Redis 处理中状态 |

活动期间普通下单接口必须拒绝专用商品。客户端不能提交用户 ID、价格、库存或预约状态。

## 5. 执行步骤

1. 新增 Trade 迁移、活动/预约领域模型和查询仓储。
2. 实现活动查询及专用商品普通下单拦截。
3. 实现准入 Lua、固定 Key 规则和预约接口；依赖不可用时快速失败。
4. 实现待发布扫描、Publisher Confirm 和相同事件重投。
5. 实现 `SeckillRequested` 消费者：消费去重、条件扣权威库存、创建订单和预约终态位于同一 MySQL 事务。
6. 对最终库存不足保存 `FAILED` 墓碑并写拒绝 Outbox；技术异常回滚并有限重试。
7. 实现 Redis 结果投影、条件补偿和订单关闭后的库存恢复。
8. 实现 Redis/MySQL 差异扫描和基础并发测试。

## 6. 异常与恢复

- Lua 成功但发布前宕机：扫描 `PUBLISH_PENDING` 并复用原事件重发。
- Confirm 未知：保持中间态并重发，不能提前补偿。
- 消费事务提交后 ACK 前宕机：重投由消费唯一键直接返回原结果。
- 迟到消息命中失败墓碑：直接 ACK，不得重新建单。
- Redis 或 RabbitMQ 不可用：拒绝新秒杀准入；普通下单不依赖两者。
- MySQL 已创建订单但 Redis 未投影：通过 Outbox 重投和对账收敛。

## 7. 测试与验收门禁

- 库存 100、1000 个不同用户并发请求，最终有效订单不超过 100且库存不为负。
- 同一用户并发 100 次最多一个预约；失败补偿后也不能重新获得资格。
- 同一 `SeckillRequested` 重投 10 次只创建一个订单并只扣一次库存。
- Redis 预扣后模拟进程宕机，扫描后能够重投或安全补偿。
- RabbitMQ 中断恢复后待发布和 Outbox 最终收敛。
- 对账满足“初始库存 = MySQL 可售库存 + 有效占用/订单”；稳定后 Redis 镜像与 MySQL 一致。
- 全量 Maven `clean verify` 通过后才允许提交本阶段。
