# 推荐系统第二轮：精排候选对齐

日期：2026-09-08。状态：已完成训练、校准、历史复评和运行测试；历史排序改善，HTTP 压力档未达门槛，候选保持工程用途。详见[执行总结](../linkverse-platform/recommendation-experiments/iterations/20260908-精排候选对齐总结.md)。

## 上一轮结论

上一轮完成工程链路和测量修复，106,114 次最终正常业务请求全部有效，未触发降级；全量单进程直连 HTTP 的 300 候选、20 并发 p95 从 442.5ms 降至 386.9ms，仍高于工具采用的 300ms 门槛。正式 NDCG@20 从 0.003242 到 0.003299，配对区间跨零，没有可靠排序收益证据。

固定候选池消融显示，移除精排比保留精排分数更高；这只是诊断线索。五项历史特征、一个正例加四个负例的小组与线上大候选池差异明显，且精排输出尺度与 MMR 相似度惩罚不匹配。上一轮同分指标已修正，本轮使用修正指标重新训练。

## 本轮唯一主线

冻结上一轮正式反馈前的召回包，维持双塔、索引、融合候选和历史特征快照不变，在其训练截止时间之后训练精排。CPU 完成 LightGBM 训练；不重复 GPU 双塔搜索，不修改 Java、中间件或依赖版本。

训练回放与在线请求调用同一个候选和特征入口，最多 500 个候选。未召回目标不强塞入候选池：该用户可不参与 LambdaRank 拟合，但必须进入最终列表验证分母。当前样本来自合成数据，没有真实曝光，因此候选中的未观察对象只用于合成回归；代码拒绝把该负例构造直接用于 REAL 数据。

## 验证和留档

先运行单元测试和 200 用户、每种特征两次搜索的冒烟；冒烟跳过测试窗口。正式执行保存源码、配置、时间审计、原始候选 ID 与标签、特征数组摘要、逐轮指标、trial、资源采样、验证逐用户指标、选定模型摘要、种子复现和全量历史回归。

随后核对旧模型响应兼容性、新包在 Linux CPU 容器中的加载和 HTTP 响应、并发性能及活动指针回滚。所有容器实验使用独立名称与模型根目录。最终是否晋级取决于完整证据，合成结果不能使模型获得自然流量候选资格。

正式入口：在推荐 Python 环境执行 `python -m linkverse_recommendation.training.ranker_iteration --config .cache/recommendation-ranker-20260908/formal-config.json`。配置内全部路径为绝对路径；重跑必须新建输出目录，不能覆盖既有运行。

本轮结果与具体复现命令将在 `linkverse-platform/recommendation-experiments/iterations/20260908-精排候选对齐总结.md` 汇总。

## 验证发现后的有界补充

首次正式验证中，扩展特征原始分数 NDCG 为 0.008590，基线为 0.004284；但覆盖率为 52.60%，低于既定 54.31% 门槛，因此正式选择保留基线。该失败完整保留，不修改原运行结果。

在尚未查看任何新精排候选测试指标的前提下，增加独立的尺度校准运行，只复用已选定的扩展特征树模型，在相同验证窗口比较 0.25、0.50、0.75 三档原始分数缩放。缩放只调整 MMR 中相关性与相似度的相对权重，精排顺序、候选、业务配额、新品约束及覆盖率门槛均不变。仅进行这一组补充；仍不达标则结束本轮并保留旧活动模型。

另补充评估器版本 5：所有对比模型统一使用 2026-02-26T15:13:00Z 请求时刻，并拒绝尚不可用的排除历史。首次运行自动生成的版本 4 结果继续留档，最终质量比较只使用统一请求时间的独立复评。
