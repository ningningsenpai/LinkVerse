## 7. 最终 HTTP 黑盒 E2E 记录

2026-08-19 在四个 Java 服务和隔离中间件真实运行状态下完成 HTTP 黑盒复验。第 4 节记录各安全契约的响应证据；以下为跨项结论：

- Gateway 注册链路返回 `201`，登录与两类令牌签发均成功；用户令牌和服务令牌的签发者、受众、主体、用途、权限、唯一标识与 TTL 均按冻结档案核验；
- Gateway 与三个资源服务的无令牌路径均为 `401`；合法令牌可穿过对应安全链到达尚未实现的业务路径并返回 `404`；
- Payment internal 严格区分用户令牌和 Trade 服务令牌；支付回调在当前阶段保持关闭，不把 `denyAll` 冒充为未来 Provider 验签实现；
- metadata、JWK、CORS、请求 ID、Problem Details、Trace 传播和日志脱敏均通过黑盒检查；
- 黑盒复验发现并修复了三项缺陷：CORS 预检错误返回 `401`、响应中出现重复 `X-Request-Id`，以及 Nacos 客户端绕过应用结构化日志并尝试写用户目录；修复后分别按第 4 节的 `200/403`、单值/重生规则和四个标准错误文件 `0` 字节通过；
- 修复后完成在线与离线全量回归，均为 `84` 个测试、`0` failure、`0` error、`0` skipped。模块计数为：`platform-core` 2、`platform-starter-web` 2、`platform-starter-security` 8、`platform-starter-observability` 10、`platform-starter-messaging` 2、Gateway 10、Identity 34、Trade 8、Payment 8。

阶段 2 不包含真实 Payment Provider 签名回调、支付业务、刷新令牌轮换、Consent、第三方登录或复杂 RBAC。这些能力不得从本次认证与 fail-closed 证据推导为已完成。
