# LinkVerse MVP 阶段 7：后端测试与交付执行设计

## 1. 目标与范围

阶段 7 完成后端集成、并发、故障和演示交付，不实现前端。最终结果必须能够在干净环境中通过脚本启动四个 Java 服务，准备测试数据，执行自动化与 k6 场景，输出对账结果和 Markdown 报告。

不生成 Swagger/OpenAPI，不把测试专用 failpoint 暴露到默认或生产 Profile，不把真实秘密和测试令牌写入仓库。

## 2. 测试分层

| 层级 | 工具 | 责任 |
|---|---|---|
| 单元测试 | JUnit 5、Mockito | 状态机、签名、金额、幂等摘要、Lua 返回映射 |
| 组件测试 | Spring Boot Test、MySQL Testcontainers | Flyway、约束、事务和 JdbcTemplate 仓储 |
| 依赖测试 | RabbitMQ/Redis Testcontainers、Toxiproxy | 发布确认、重投、缓存和网络故障 |
| Provider 测试 | WireMock | 超时、重复通知、错误字段和未知退款结果 |
| HTTP 并发 | k6 2.2.0 | 普通下单、秒杀、支付及回调链路的吞吐和延迟原始数据 |
| 黑盒验收 | PowerShell | 四服务启动、接口结果、故障恢复、对账和报告编排 |

单元/组件测试使用 `*Test`，跨容器集成测试使用 `*IT` 并由 Failsafe 执行。测试 Profile 的 barrier/failpoint 只通过测试 Bean 或测试配置提供。

## 3. 脚本交付

| 脚本 | 行为 |
|---|---|
| `start.ps1` | 启动中间件与四个 Java 服务，保存 PID 和日志并等待健康 |
| `seed.ps1` | 初始化固定商品、活动和测试用户，输出脱敏摘要 |
| `verify.ps1` | 运行静态检查、Maven 单元/集成测试和基础设施验证 |
| `fault-test.ps1` | 执行重复、竞态、依赖中断和恢复场景 |
| `reconcile.ps1` | 输出订单、支付、退款、库存和消息差异 |
| `acceptance.ps1` | 顺序编排 seed、verify、k6、fault-test 和 reconcile；任一步失败即非零退出 |
| `replay.ps1` | 按事件 ID 重放停车消息，要求显式确认 |
| `clean.ps1` | 二次确认后仅停止 `linkverse-mvp-*` 进程和容器；默认不删命名卷 |

所有脚本从 `$PSScriptRoot` 解析仓库路径，不依赖调用者当前目录。运行产物写入被 Git 忽略的 `linkverse-platform/artifacts/`。

## 4. k6 场景与报告

k6 版本写入 `versions.env` 并在运行前检查。场景至少包括：

- 普通订单同键并发重放和最后一件库存竞争；
- 库存 100、1000 用户秒杀；
- 单用户 100 次重复预约；
- 支付创建、合法回调、回调重放和状态查询；
- 支付创建/关闭及支付成功/关单竞态。

k6 阈值只用于正确性失败和非预期 HTTP 错误。吞吐、p95、p99 和丢弃迭代记录为实测数据，不在执行前设置宣传性目标。原始 JSON、JUnit XML、环境摘要和 Markdown 汇总均保留在 artifacts。

## 5. 最终接口测试文档

阶段完成后生成 `13-MVP接口与测试报告.md`，覆盖认证、交易、支付、内部支付、Provider 回调和秒杀接口。每个用例记录：

1. 方法、路径、鉴权和前置条件；
2. Header、路径参数、请求体和测试目的；
3. 预期状态码、响应字段和业务状态；
4. 实际响应摘要、执行时间和结论；
5. 关联自动化测试或 artifacts 报告路径。

JWT、密码、客户端秘密、HMAC 密钥和完整签名必须使用占位符或脱敏摘要。
