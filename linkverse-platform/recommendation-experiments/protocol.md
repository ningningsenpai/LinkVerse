# Trade 推荐闭环实验协议

## 1. 数据准备

1. 对旧 CSV 只读执行迁移，删除 `rating`、`last3m` 和全历史聚合字段。
2. 将旧 `buy` 改名为 `legacy_buy_signal`，全量标记 `SYNTHETIC`。
3. 对真实闭环导出使用 Trade 只读账号和外部 HMAC Secret；原始用户 ID 不进入 Python。
4. 检查重复事件、脏行、OOV、时间顺序和特征截止时点。
5. 真实事件按 delivery、会话或订单归因链聚合；30 分钟未转化曝光和主动退款作为硬负样本，运营退款不改变兴趣标签。
6. 负采样只能读取样本时刻已经发布的商品；`REAL` 与 `SYNTHETIC` 禁止进入同一训练运行。

## 2. 固定时间切分

| 窗口 | 比例 | 用途 |
|---|---:|---|
| 基础训练 | 60% | 拟合召回器、双塔和初始特征 |
| 调参与早停 | 15% | 30 次双塔搜索与 50 次 LambdaRank 搜索 |
| 反馈收集 | 10% | HTTP 闭环与反馈后完整重训 |
| 最终测试 | 15% | 初始/新模型同用户同上下文盲测 |

最终测试窗口不能参与参数选择、早停、词表构建或累计特征计算。

## 3. 训练与调参

1. 训练前必须运行 CUDA 检查，记录 GPU、显存、PyTorch 和 CUDA 运行时。
2. 双塔搜索 embedding 维度、隐藏层、学习率、权重衰减、batch、dropout、负样本数和 temperature；最多 40 epoch，patience 5，启用 AMP。
3. LambdaRank 在 CPU 上独立执行 50 次搜索。
4. 最佳双塔参数使用随机种子 `20260903`、`20260917`、`20261001` 重训，报告均值和标准差。
5. 主指标为 NDCG@20，同时记录 Recall@50、覆盖率、多样性和延迟。

## 4. 用户回放

固定选择五类匿名画像：重点单一兴趣、多兴趣、只加购未购买、价格敏感和冷启动。每名用户回放至少三个按时间排序的会话，总计不少于 15 次 Top20 推荐。每次记录：

- 推荐前历史及分类、作者、价格偏好；
- Top20 对象、分数、来源、原因和模型版本；
- 与后续留出行为的 HitRate、NDCG 和分类吻合度；
- 覆盖率、新颖度、列表内多样性和响应时间。

## 5. HTTP 反馈闭环

1. 通过 Gateway 请求推荐，渲染后逐项上报 `IMPRESSION`。
2. 命中留出目标时上报 `DETAIL_OPEN`，执行加购、下单和 Mock 支付。
3. 至少触发一次 `PaymentRefunded`；分别验证用户主动/质量原因会形成负反馈，而 `LATE_SUCCESS` 等运营退款只保留事实。
4. 用只读导出器生成新快照，合并反馈后完整重训，禁止在线微调。
5. 在最终窗口进行旧模型和新模型的同上下文比较，再走一轮实际 Trade API。

## 6. 晋级与回滚

只有当新模型 NDCG@20 同时优于热门基线和当前模型、覆盖率下降不超过 10%、Python p95 不高于 300ms、Trade p95 不高于 800ms 时，才能把它标记为候选冠军。模型仍需先校验、影子比较，再原子替换活动指针；任何失败均保留旧模型并记录原因。

并发验收分两层记录：`serving-benchmark.json` 记录 20 并发的 Python 进程内 CPU 推断；
Gateway、Trade、服务 JWT、熔断和网络开销必须由实际 HTTP 压测单独记录。前者通过不能推导后者通过。
