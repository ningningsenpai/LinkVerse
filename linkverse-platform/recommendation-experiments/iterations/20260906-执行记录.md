## 已测结果

旧模型在公共历史排除口径下，全量 7,532 名可评估用户的 NDCG@20 从 0.007866 升到 0.010494，Recall@50 从 0.044855 升到 0.055344。但旧在线补位路径几乎全部违反类目配额，这些结果不能直接代表满足约束后的推荐效果。

新冒烟模型使用冻结时间戳边界，测试窗口有 7,581 名用户，其中 7,541 名可评估；同种子重复训练权重差为 0。反馈前后 NDCG@20 为 0.006118 / 0.006019，配对差值约 -0.000098，95% bootstrap 区间跨零；Recall@50 为 0.047894 / 0.053556。这只能说明冒烟流程可运行，不能宣称排序质量提升。该次评估前模型的 31 个配额违规来自公共历史在重排后的二次过滤，评估器版本 3 已把排除移到重排前，后续统一口径复评。

初次真实快照只有 17 个会话归因样本，冻结窗口剔除跨边界链后为 10 / 1 / 1 / 2，样本量不足以得出自然用户质量结论。该模型仅以 `ENGINEERING` 用途加载。

## 实际暴露的故障与处理

| 故障 | 证据与处理 |
|---|---|
| Windows 长 SQL 参数启动 Docker 失败 | 先表现为输出重定向异常，直接运行后定位到命令行长度限制；改用标准输入传输整段夹具事务，未修改用户的基础设施脚本 |
| 测试记录器不支持购物车列表响应 | 初次 HTTP 运行保留 FAILED 记录；修复响应摘要解析后另开运行 |
| 支付成功而订单不收敛 | RabbitMQ 拒绝 Java 使用的旧账号；启动脚本统一使用 Compose 已收敛账号，重启 Trade/Payment 后 15 个会话和两种退款通过 |
| Windows 运行 JAR 被锁 | 导出首次构建失败；服务改从独立运行副本启动，导出使用同包内的独立最小 Spring 上下文，禁止带起业务消费者与定时写任务 |
| 导出配置被在线扫描 | 导出配置增加专用 profile，恢复 Trade 并验证健康 |
| Recommendation 客户端未初始化 | 本地旧配置缺少 bootstrap 开关；补齐准备脚本和忽略配置，沿用原密钥初始化专用最小权限客户端 |
| Python 拒绝合法服务 JWT | Identity 的 scope 为字符串数组，原验证器只接受字符串；兼容两种已签名表示，保留权限约束并补测试 |

## 可复现入口

- `python -m linkverse_recommendation.training.iteration --config <配置>`：基线或训练，保存源码、配置、资源、epoch、trial、切分、模型与评估。
- `scripts/recommendation/prepare-fixtures.ps1`：建立独立编号的本地商品及用户夹具。
- `python -m linkverse_recommendation.training.local_validation --fixture <夹具> --output <运行目录>`：真实 HTTP 反馈闭环。
- `scripts/recommendation/export-snapshot.ps1 -TrafficOrigin SCRIPTED -MinimumListingId <起点> -MaximumListingId <终点> ...`：只读导出夹具范围并校验 Parquet。
- `scripts/recommendation/start-serving.ps1 -ModelRoot <模型根> -Build`：启动 CPU 推荐容器并检查模型 readiness。
- `python -m linkverse_recommendation.training.http_benchmark --config <配置>`：逐层性能/长稳测试，分别统计已知与冷启动用户、有效模型率、降级率和原始延迟。

## 升级与回滚原则

每轮顺序为：冻结数据与源码 → 核验标签时间 → 冒烟 → 固定验证集搜索 → 三种子及同种子重复训练 → 全量与消融评估 → 工程 HTTP 闭环 → 低噪声性能及故障测试 → 审核门禁 → 原子换版。任一阶段失败保留原始证据并另开运行，不覆盖历史结果。

工程模型可用于本地回归。回归候选需要与模型包摘要绑定的质量、数据隔离、测试、HTTP、延迟和回滚证据；自然流量候选还必须具有独立确认性证据。旧版本保持可用，坏包加载失败不能中断已加载版本的请求。
