# 推荐系统复现与迭代升级步骤

本轮实测结论见[执行总结](20260906-执行总结.md)。以下操作顺序沿用本轮已执行的工具；再次运行必须新建输出目录，不能覆盖原始证据。全量质量和性能尚未全部通过，当前模型用途保持 `ENGINEERING`。

## 1. 固定环境与输入

在 `D:/Code/ning/LinkVerse` 执行。沿用 JDK 21、仓库 Maven Wrapper、已锁定的 Python 环境和隔离 Compose；不更新依赖来改变性能对照。

```powershell
. ./linkverse-platform/scripts/_delivery.ps1
$context = Initialize-LinkVerseDeliveryEnvironment
$recEnv = (Resolve-Path 'linkverse-platform/recommendation/.venv-conda').Path
$env:PATH = "$recEnv;$recEnv\Library\bin;$recEnv\Scripts;$env:PATH"
$env:PYTHONIOENCODING = 'utf-8'
$env:PYTHONDONTWRITEBYTECODE = '1'
$env:OMP_NUM_THREADS = '1'
$env:OPENBLAS_NUM_THREADS = '1'
$env:MKL_NUM_THREADS = '1'
$python = Join-Path $recEnv 'python.exe'
```

加载脚本只从已忽略的本地环境读取凭据，不把凭据复制进实验配置、日志或文档。训练用 8 个 CPU 线程，GPU 单任务；性能测试期间停止本轮训练和 Java 构建，不停止其他用户应用。

每轮先记录源码摘要、数据文件哈希、快照 `exported_at`、数据来源和冻结时间边界。脚本数据与自然流量分别导出。成熟曝光、退款归因、未来标签和跨窗剔除通过数据审计后再训练。

## 2. 建立新运行配置

本轮正式配置保存在 `runs/trade-formal-20260906T060941Z/config.json`，对应历史合成回归。修正后的本地脚本配置保存在 `runs/trade-local-corrected-20260906T084509Z/config.json`。

```powershell
$stamp = [DateTimeOffset]::UtcNow.ToString('yyyyMMddTHHmmssZ')
$base = 'linkverse-platform/recommendation-experiments/runs/trade-formal-20260906T060941Z/config.json'
$next = Get-Content -LiteralPath $base | ConvertFrom-Json
$next.output = Join-Path (Get-Location) "linkverse-platform/recommendation-experiments/runs/trade-next-$stamp"
$next.model_root = Join-Path (Get-Location) "linkverse-platform/recommendation/artifacts/next-$stamp"
$nextConfig = Join-Path (Get-Location) ".cache/recommendation-next-$stamp.json"
$next | ConvertTo-Json -Depth 15 | Set-Content -LiteralPath $nextConfig -Encoding utf8
```

这个示例保留历史数据和固定切分，适合重跑修正后的精排指标。做确认性验证时，应在运行前改为新的未查看数据窗口并冻结；不能把已查看的本轮测试集重新命名为盲测。

## 3. 测试、训练与评估

```powershell
& $python -m pytest linkverse-platform/recommendation/tests -q -p no:cacheprovider
& $python -m linkverse_recommendation.training.iteration --config $nextConfig
& $python -m linkverse_recommendation.training.summarize_run --run $next.output
```

涉及 Java 推荐契约、事务或过滤的变更，从 `linkverse-platform/backend` 执行 `./mvnw.cmd -pl linkverse-trade -am test`。本轮完整 Trade 与共享模块测试通过，新增 HTTP 合同与阶段遥测也已针对测试。本轮没有在运行中的 Payment、Gateway JAR 上执行全仓 `clean verify`；复现全仓构建时，应先使用独立运行副本或隔离构建目录。

先 5 次双塔 + 5 次精排冒烟，再 30 + 50 正式搜索。固定验证集选择超参数、早停轮数；三个种子都保存，同种子再重复一次。第一个固定种子用于模型包，不按测试得分挑种子。

依次检查 `status.json`、trial/epoch 曲线、训练资源、`evaluation.json`、逐用户观测与分群分母。无正目标记为空，不填零；成员变化的冷启动分群不能直接做配对比较。验证集同分指标已经修正为期望增益，下一轮还要改进真实候选组、相关性特征和重排分数尺度。

## 4. 真实反馈闭环

沿用推荐专用夹具脚本建立新的独立编号；经 Gateway 执行 HOME、DETAIL、CART、曝光、下单、支付、退款与终态验证。支付提供方使用本地 Mock。推荐响应必须来自预期活动版本，数据库降级不能作为模型成功。

`training.local_validation` 保存真实 HTTP 过程；`scripts/recommendation/export-snapshot.ps1` 按夹具编号范围只读导出，标注 `SCRIPTED`；待曝光成熟后审计标签再重训。重复下单、重复支付、主动退款和迟到补偿必须保留确定性用例。

不要把压测中的高频推荐投递数当作自然曝光数。用户可见性事件、成熟负反馈和自然实验需要单独采集。

## 5. 固定版本进行运行验收

对模型包先执行校验与预热，再通过 `serving.activate` 原子更新指针；指定 `ENGINEERING` 仅用于隔离工程验证。`scripts/recommendation/start-serving.ps1` 启动现有 Compose 推荐服务并检查实际 readiness 版本。

完整目录与 120 商品业务夹具分别测试。使用 `training.http_benchmark --config <新配置>` 执行每档 30 秒预热、120 秒采样，记录 1/5/10/20 并发，日常 100 与压力 300 候选分别报告。客户端固定 `trust_env=False`，按请求写入状态、预期版本、场景、分群、延迟和降级原因。

20 并发达标后才探索 30/50。随后执行 30 分钟、20 虚拟用户、每轮 1 秒思考时间的长稳与独立 5 分钟复跑；这与 20 个持续在途请求的峰值压力不同，必须单列实际吞吐。用 `training.queue_monitor --run <已开始运行>` 采集队列，用 `training.runtime_snapshot` 留存分阶段计数与连接池状态，资源采样失败必须标为不可用。

`training.fault_validation` 仅操作隔离项目推荐容器，覆盖实际 JWT 拒绝、坏包、越界指针、并发换版、暂停/停止、无活动模型、信号量饱和和恢复；其 `finally` 恢复原始指针。每次故障单独报告恢复时间，不混入正常性能统计。

## 6. 晋级和回滚

晋级证据绑定目标 `manifest.json` 的 SHA-256。质量、数据隔离、测试、真实 HTTP、延迟和回滚全部通过才使用 `REGRESSION_CANDIDATE`；自然流量候选还要求自然数据和独立确认性证据。未执行记为未执行，失败不能因工程链路正常而被改为通过。

回滚到同一模型根下已保存的旧包后，必须检查 readiness 和连续实际请求的模型版本。另存镜像 ID、实际运行 JAR 摘要和模型指针；需要回退工程代码时使用已保存镜像与 JAR 副本，模型回滚不删除支付事实或反馈记录。

每轮最后填写“变更假设、冻结输入、前后指标、分母、资源趋势、失败原因、晋级决策、下一项实验”。本轮最优先的后续实验是修正指标下的正式精排搜索和真实候选组训练；全量模型包紧凑化及加载期间的服务可用性单独立项验证。
