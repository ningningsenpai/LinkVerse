# LinkVerse 运行与测试

## 环境要求

当前本地交付以 Windows PowerShell 为主要入口，需要准备：

- Docker Desktop，并确保 Docker Engine 已启动；
- PowerShell 7；
- JDK 21；
- 推荐训练需要 Python 3.12、Conda 和兼容的 CUDA 环境；
- 完整性能测试使用锁定版本 k6 2.2.0。

Java 服务使用仓库内 Maven Wrapper 3.9.10，不需要单独安装 Maven。训练数据、模型权重、索引和本地密钥不进入 Git，需要由本地准备或训练流程生成。

## 环境准备与启动

在项目根目录执行：

```powershell
Set-Location .\linkverse-platform
.\scripts\prepare-local.ps1
.\scripts\start.ps1 -JavaHome $env:JAVA_HOME
```

`prepare-local.ps1` 生成被 Git 忽略的本地密钥、RSA 密钥对和环境配置，已有值不会被无条件覆盖。`start.ps1` 会启动隔离中间件、构建后端，并依次启动 Identity、Payment、Trade 和 Gateway。

如果 `JAVA_HOME` 指向 JDK 根目录，可按上例显式传入。脚本缺省值对应项目维护环境中的 JDK 路径，其他机器不应依赖该缺省值。

| 单元 | 本地端口 | 启动方式 |

| Gateway | 18080 | 宿主机 Java 进程 |
| Identity | 18081 | 宿主机 Java 进程 |
| Trade | 18082 | 宿主机 Java 进程 |

| Redis | 16379 | Docker Compose |

容器与服务只绑定本机地址，Compose 项目名和网络名与其他本地项目隔离。详细边界见[系统架构：本地部署方式](系统架构.md#本地部署方式)。

## 测试入口

后端代码验证从 `linkverse-platform/backend/` 执行：

```powershell
.\mvnw.cmd clean verify
```

运行态验证从 `linkverse-platform/` 执行：

```powershell
.\scripts\verify.ps1
.\scripts\seed.ps1 -UserCount 1000
.\scripts\acceptance.ps1
.\scripts\fault-test.ps1
.\scripts\load-test.ps1
```

| 入口 | 验证内容 |
|---|---|
| `verify.ps1` | Compose 配置、容器健康、端口和隔离边界；`-StaticOnly` 只执行静态检查 |
| `seed.ps1` | 创建演示商品、秒杀活动、测试用户和短期令牌 |
| `acceptance.ps1` | 认证、普通交易、支付、秒杀、消息和恢复接口 |
| `fault-test.ps1` | 重复请求、回调重放、消息重投、依赖中断和并发竞态 |
| `load-test.ps1` | 普通订单、支付和秒杀 k6 场景，并保存原始与汇总结果 |

测试不应连接持久化或生产中间件。集成测试在需要真实数据库边界时使用 Testcontainers；外部支付由 Mock 渠道替代。

## 单独启用推荐

推荐服务需要一个已经包含 `active-model.json` 的模型根目录：

```powershell
Set-Location .\linkverse-platform
.\scripts\recommendation\start-serving.ps1 -ModelRoot 'C:\path\to\models' -Build
```

脚本构建 Recommendation 镜像，通过 `recommendation` Compose profile 启动服务，并把模型目录只读挂载到容器。Java 服务仍由 `start.ps1` 在宿主机启动。没有有效模型包时，Recommendation 会拒绝就绪，Trade 保留业务侧热门降级能力。

## 推荐训练与评估

首次创建环境：

```powershell
Set-Location .\linkverse-platform\recommendation
conda env create -f environment.yml
conda activate linkverse-recommendation
python -m pip install --no-deps -e .
python -m linkverse_recommendation.training.cuda_check
pytest
```

`prepare-local.ps1` 会把推荐 HMAC 密钥写入 `linkverse-platform/infrastructure/.env`，但不会自动导入当前训练终端。旧数据迁移、Trade 快照和在线请求必须始终复用该文件中的同一个 `RECOMMENDATION_USER_HMAC_SECRET`，否则同一用户会生成不同的 `user_key`。下面通过项目环境加载器把已有值导入当前进程，不打印密钥：

```powershell
Set-Location .\linkverse-platform
. .\scripts\_infrastructure.ps1
$infrastructure = Get-LinkVerseInfrastructureContext
Import-LinkVerseInfrastructureEnvironment `
  -Context $infrastructure `
  -EnvironmentFile $infrastructure.EnvironmentFile
.\scripts\recommendation\import-legacy.ps1 `
  -Items 'C:\path\to\items_new.csv' `
  -Users 'C:\path\to\users_new.csv' `
  -Interactions 'C:\path\to\interactions_new.csv' `
  -Output 'C:\path\to\trade-synthetic'
```

本地 `.env` 已被 Git 忽略；不得在命令、日志或文档中写出实际密钥。若文件尚未生成，应先执行[环境准备与启动](#环境准备与启动)中的 `prepare-local.ps1`。

基础完整训练使用直接参数：

```powershell
Set-Location .\linkverse-platform\recommendation
python -m linkverse_recommendation.training.cli `
  --dataset 'C:\path\to\trade-synthetic' `
  --output 'C:\path\to\candidates' `
  --require-cuda
```

冻结召回后的精排迭代和验证集分数校准使用版本化 JSON 配置：

```powershell
python -m linkverse_recommendation.training.ranker_iteration `
  --config 'C:\path\to\ranker-config.json'
python -m linkverse_recommendation.training.ranker_calibration `
  --config 'C:\path\to\calibration-config.json'
```

基础入口的参数、精排配置文件、数据清单、随机种子、试验记录和评估产物需要一同归档。数据与模型包内容见[推荐数据与训练：训练与模型包](推荐数据与训练.md#训练与模型包)。

## 日志与测试结果

本地脚本将运行状态、服务日志、种子数据和测试产物写入被 Git 忽略的运行目录。推荐实验的可追溯摘要保存在 `linkverse-platform/recommendation-experiments/`，大型数据、模型权重、Faiss 索引和完整试验缓存不提交到仓库。

对外引用测试结果时，应同时保留测试时间、代码版本、环境、并发、请求总量、候选规模和数据来源。当前可公开复核的摘要见[迭代与验证结果：结果说明](迭代与验证结果.md#结果说明)。

## 停止与清理

停止本地服务并保留数据卷：

```powershell
Set-Location .\linkverse-platform
.\scripts\clean.ps1
```

只有明确需要重置本地数据时，才同时使用 `-RemoveData -ConfirmProject linkverse-mvp`。脚本会核对记录的 Java 进程命令行和 Compose 项目名，避免终止无关进程或删除其他项目的数据卷。

## 已知限制

- 当前支付渠道为 Mock，实现的是回调、关单、退款补偿和对账语义，不代表已接入真实支付机构。
- Forum、聊天和 Vue 前端仍属于后续整合范围，当前运行闭环以交易与推荐为主。
- 推荐模型与训练数据不随仓库分发，启用服务前需自行生成符合 Schema 的模型包。
- 当前压测结果来自单机本地环境，只说明所记录条件下的表现，不能外推为生产容量承诺。
